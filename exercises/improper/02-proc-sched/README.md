# 02 · 进程管理：软件模拟进程调度（FIFO → 约束 → 优先级）

> 不正经赛道 · 第 2 课 —— 纯软件、host 直接跑。
> 一句话母题：**调度 = 存储结构（谁在就绪）+ 选择策略（选谁）**，二者解耦。

## 0. 这节课在讲什么

进程就是一张卡片（PCB），调度器是发牌人。本课不切真实寄存器、不碰时钟中断，只用一个就绪结构 + 一个「选下一个」的策略，把「调度」拆到最朴素。你逐题做三个发牌人：

1. **FIFO**：老实人，先到先得。
2. **约束调度**：有「潜规则」——某进程永不上桌（GHOST），某进程必须等另一个之后（B 在 A 后），其余随意。
3. **优先级**：把就绪 `Vec` 换成会自动冒出「最大牌」的优先队列。

对应真实系统：rcore `ready_queue: VecDeque<ProcId>`、xv6 `scheduler()`、Linux CFS 取红黑树最左、RISC-V PLIC 的中断优先级仲裁。

## 1. 数据模型

```
struct Proc { pid: u32, prio: u32, tag: u32 }   // tag: 0=普通 1=GHOST 2=A 3=B
```

## 2. 你要填的三个函数（`sw/rust/src/main.rs` 或 `sw/c/sched.c`）

| 函数 | 要求 | 判据 |
| :-- | :-- | :-- |
| `run_fifo` | 按到达顺序返回 pid | 执行序 == 入队序 → `FIFO_PASS` |
| `run_constrained` | 去 GHOST；B 恒在 A 后；其余各一次 | 三不变量全中 → `SCHED_PASS` |
| `run_priority` | 高优先先出；平级按到达（稳定） | 优先级单调不增 + 平级 FIFO → `PRIO_PASS` |

三者皆过再打印 `ALL_PASS`。约束调度的 `B 在 A 后` 可二选一实现：
`// TODO[a]` 入队门控（A 未完成前不放 B） / `// ELSE[b]` 选择时把 B 挪到 A 后。

## 3. 完成标准 (DoD)

- [ ] `FIFO_PASS`：FIFO 执行序 == 入队序。
- [ ] `SCHED_PASS`：GHOST 不跑 / B 恒在 A 后 / 其余各一次。
- [ ] `PRIO_PASS` + `ALL_PASS`：高优先先出、平级 FIFO 兜底。
- [ ] C/Rust 任一条全过（必修）；另一条也过计辅助分。
- [ ] 能说清「存储结构 / 选择策略」为何要解耦（思考题）。

## 4. 思考题（`THINKING.md` 作答即可通过）

1. 你的「B 恒在 A 之后」用了**入队门控**还是**选择跳过**？若 A 永远不结束，两种实现下 B 的命运有何不同？对应真实 OS 的什么（依赖 / `wait` / D 状态）？
2. 优先级调度会让低优先级进程**饿死**。给一个必然饿死的输入序列，并说明真实系统怎么缓解（优先级老化 aging / 时间片 / 多级反馈队列 MLFQ）。
3. 把「选最高优先级就绪任务」从软件优先队列换成硬件**优先编码器**，硬件省了什么、又被什么限制（位宽 / 可表达的优先级数 / 就绪槽位上限）？联系 RISC-V PLIC。
