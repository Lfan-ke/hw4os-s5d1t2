# 18-5 思考题 · 从 MCU 裸中断到 MPU 受控 syscall（参考答案）

> 母题：**中断 = 硬件驱动的间接跳转；syscall = 被 ABI 驯化、过特权级的受控陷入。**

## 1. 为什么 OS 不让用户态直接跳到内核函数地址？

MCU 时代向量表就摆在内存里，谁都能按号查地址、直接 `jmp` 进 handler——没有门卫。
长出特权级、跑起 OS 后，这样做有三宗罪：

- **隔离**：用户态若能跳到任意内核地址，就能跳过参数检查、跳进内核函数的中段，
  绕开权限校验读写内核数据——保护形同虚设。`ecall` 强制「只能落在 `stvec` 这一个入口」，
  内核在入口统一存上下文、查 `scause`、做安检，才往下分发。
- **ABI 稳定**：把「内核函数的地址」换成「调用号」，用户程序不再依赖内核的内存布局。
  内核重新编译、函数搬家、地址全变，用户二进制只认 `a7=64` 仍旧能 write。
  地址是实现细节，号是契约。
- **安检门**：`ecall` 抬权 U→S 是一道**单一可控的关卡**。所有跨界请求都在这里收口，
  内核可以在此做参数校验、配额、审计、信号处理——一个门，好守。

一句话：把「地址」换成「号」，换来了**隔离 + 前向兼容 + 可审计的单一入口**。

## 2. 向量化 vs 非向量化：多连几根线，省掉哪段软件？

- **direct（非向量化）**：`stvec.MODE=0`，所有异常都跳到同一个入口，
  软件进门后要先**读 `mcause/scause`、再一长串 `if/switch` 自己分派**到对应 handler。
  硬件最省（一根 base 即可），软件每次陷入多花「读 cause + 跳转表查找」的开销。
- **vectored（向量化）**：`stvec.MODE=1`，硬件直接 `pc = base + 4*cause`，
  **按号在表里查地址、一拍跳到位**，省掉软件那段「取号—查表—跳转」。
  代价是硬件多了一个移位器+加法器（`cause<<2` 再加 base）和「每号一格」的入口表布局约束。

接回 `01-hw-vlan` 的软硬成本核算：**向量化把分派从软件搬到硬件**——
多连几根线（一个常量移位 + 一个加法器）换来每次陷入恒定的、与号数无关的 O(1) 派发延迟。

- 该选 **vectored**：中断号多、且对**中断延迟**敏感的实时/高频场景
  （如 Cortex-M 的 NVIC：每个外设一个向量，进中断零软件分派开销）。
- 该选 **direct**：异常种类少、或希望**集中在一处统一处理**（先存完整上下文再慢慢分派）的通用 OS
  内核陷入路径——少量硬件、最大灵活性，rcore/xv6 的 trap 入口正是 direct 风格。

## 3. RISC-V `ecall`+寄存器约定 vs CISC 专用 `syscall`/`int 0x80`：负担放哪？

两者都要「触发陷入 + 取号 + 分派」，区别在**把多少塞进一条指令**：

- **RISC-V**：`ecall` 只负责「陷入并抬权」，**取号/取参全靠寄存器约定**（`a7`/`a0..a5`），
  分派是内核软件查 `scause==8` 后按 `a7` switch。硬件极简（一条通用陷入指令打通所有用途：
  syscall、SBI、断点），代价是号与参数的语义完全由 ABI 软件约定承载。
- **CISC（x86）**：`int 0x80` 走 IDT 门、`syscall` 配 `MSR_LSTAR` 等专用寄存器，
  指令本身就携带更多「陷入语义」，微码替你切栈/切权限。硬件复杂、指令专用，
  但单条指令开销更可预测、对编译器更省事。

权衡：**负担放硬件**（CISC）→ 指令少、微码厚、灵活性低；
**负担放软件**（RISC-V）→ 硬件精简正交、一条 `ecall` 多用，分派与约定的复杂度上移到内核+libc。
这正是 RISC vs CISC 的老账，落在 syscall 上的一个切面。

## 4. 固定 `a7`=号、`a0..a5`=参、`a0`=返 的意义；若每版内核乱改会怎样？

把寄存器约定钉死成 **ABI**，是用户态与内核之间**永不重新编译也能对接**的契约：

- **libc 是契约的封装层**：`write()` 包装器把参数装进 `a0/a1/a2`、号装进 `a7`、执行 `ecall`、
  从 `a0` 取返回值/errno。只要约定不变，libc 与海量已编译二进制就一直能用。
- 若**每个内核版本都改寄存器约定**：所有 libc 必须随内核版本重编、分发；
  任何**已编译的旧二进制**（没源码的、静态链接的）在新内核上调号即错位——
  参数落到错误寄存器、返回值取错地方，轻则功能崩、重则把垃圾当指针。
  整个「一次编译、处处运行」的生态崩盘。
- 所以 Linux 把 syscall 号与寄存器约定当作**近乎永不破坏的稳定边界**（号只增不改、约定不动），
  新功能靠**新增号**而非改旧约定——这就是 GNU 规范化的价值：稳定的调用约定 + 分发表 + libc 包装。
