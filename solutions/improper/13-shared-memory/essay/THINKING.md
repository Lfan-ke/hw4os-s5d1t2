## 1. 共享内存（零拷贝）vs 消息传递（拷贝）

- **共享内存**：双方映射同一份物理字节，写入对方立刻可见，**零拷贝**、吞吐高、延迟低。
  代价是**同步复杂**：必须自己用标志位 / 锁 / 内存序保证「写在前、读在后」，否则撕裂读、
  竞态、ABA。失败模式集中在**协调出错**（一方崩溃后共享区残留半成品状态，需要清理/恢复）。
  适用：大块数据、高频交互，如视频帧缓冲、virtio vring、数据库共享缓冲池。
- **消息传递**：内核（或运行时）拷贝一份送达，**语义干净**——消息是不可变快照，发送后双方
  互不干扰，天然带「边界」。代价是**拷贝开销**与**系统调用开销**。失败模式更可控（消息丢了
  就是丢了，不会留下半截共享状态）。适用：小消息、跨信任域、需要解耦，如 shell 管道、RPC。
- **谁更划算举例**：传 1 GB 数据给同机另一进程——共享内存零拷贝完胜（消息传递要拷 1 GB）；
  传一个 8 字节命令给远端服务——消息传递更划算（建共享映射+同步的固定成本远大于拷 8 字节）。

## 2. 「OS 所在的 CPU 也是一台物理设备」

CPU 不过是一块能取指执行的硬件，和网卡/磁盘控制器一样挂在同一条总线上、访问同一片物理内存。
所以「进程↔进程共享」与「设备↔OS（MMIO）共享」是**同一模型**：

- 同一份物理字节：进程间是两个 PTE 指向同一 PPN；设备↔OS 是 MMIO 寄存器/共享 RAM 区，
  双方各按自己的地址去访问同一片字节。
- 同一套协调协议：进程间用 `ready` 标志 / 锁；设备↔OS 用 `avail` 标志 + `head/tail` 指针 +
  doorbell。本实验子 3（邮箱握手）与子 4（共享环）就是这套协议的软件版与软硬同构版。

**协调方/仲裁者分别是谁**：
- 进程↔进程：仲裁者是 **OS/硬件提供的同步原语**（futex、原子指令、内存屏障），双方是对等的
  软件线程。
- 设备↔OS：仲裁者是**约定的寄存器协议本身**（谁写 tail、谁写 head、谁拉 doorbell、谁读 avail），
  外加总线/缓存一致性硬件兜底原子性。一方是 CPU 上的驱动，一方是设备状态机。

## 3. cache 一致性 / DMA 一致性 / 直接映射区

- **两个 CPU 核共享同一物理行**：各自 L1/L2 里可能有该行的副本。若没有 cache 一致性协议
  （MESI 等），核 A 写了自己的 cache、核 B 还读到旧副本 → 看不到更新。一致性协议靠总线
  嗅探/目录使写传播、让旧副本失效。
- **CPU 与 DMA 设备共享**：DMA 直接读写物理内存，绕过 CPU cache。若 CPU 把数据留在 write-back
  cache 里没刷回，设备 DMA 读到的是内存里的旧值；反过来设备 DMA 写了内存，CPU cache 里还是
  旧副本。需要 **cache flush/invalidate** 或一致性 DMA（dma_map/dma_sync）来对齐。
- **为什么 SMP 的「拍卖行」槽位放直接映射区**：核间共享槽必须让所有核用**同一个稳定的物理地址**
  去访问同一份字节。直接映射区（物理地址 + 固定偏移）对所有核一致、无需各自建私有页表映射，
  上下文切换也不变；若放进各进程虚拟地址空间，则每个核/进程的虚地址不同、映射可能被换出，
  无法保证「同一份物理字节」这一前提，反而要靠额外别名映射去对齐——把简单问题复杂化。
