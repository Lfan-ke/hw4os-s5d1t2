# 07-ipc 思考题参考答案（essay 变体）

## 1. 为什么 B 必须「先写 RESULT 再置 DONE」？反过来会读到什么垃圾值？

因为 A 是靠 **DONE 位**作为「数据已就绪」的唯一信号。协议约定：DONE=1 ⇒ RESULT 已经写好。
若 B 反过来「先置 DONE 再写 RESULT」，就出现一个**中间态窗口**：DONE 已经是 1，但
RESULT 还是上一轮的旧值（或半写入的垃圾）。A 在这个窗口里采样，就会把垃圾当成结果用走，
即「过早就绪」（本课的 EARLY 判据）。

这本质是**内存序 / 可见性**问题。正确顺序是一个 **release-acquire** 配对：
B 端写 RESULT、再以 **release** 语义置 DONE；A 端以 **acquire** 语义读 DONE，一旦读到
DONE=1，则保证 DONE 之前的所有写（RESULT）都对 A 可见。本实验 Rust 用
`Ordering::Release`/`Ordering::Acquire`，C 用 `memory_order_release`/`memory_order_acquire`，
硬件里则用「同一拍内 RESULT 字段先稳定、DONE 沿后采样」来表达。底层对应一条 `fence`
（RISC-V `fence rw,rw`）或带 acquire/release 的原子指令，阻止编译器/CPU 把「写 RESULT」
重排到「置 DONE」之后。

## 2. 自旋锁 vs 阻塞锁：各自浪费/节省了什么？怎么选？

- **自旋锁（spin）**：拿不到锁就原地忙等（不断 `tas`）。
  - 省：不进内核、不做上下文切换，**唤醒延迟极低**；临界区一释放马上就能进。
  - 费：等待期间 **白烧 CPU**；若临界区长或持锁者被换下，自旋就是纯浪费。
- **阻塞锁（block）**：拿不到锁就把自己挂起、让出 CPU，等释放时被唤醒。
  - 省：等待期间 **不占 CPU**，别的任务能跑。
  - 费：挂起 + 唤醒 + 上下文切换有**固定开销**和较大延迟。

选择原则：
- **临界区很短** → 自旋（切换开销 > 自旋开销）。
- **临界区很长 / 可能睡眠** → 阻塞。
- **单核** → 持锁者不在跑时自旋毫无意义（拿锁的人根本没机会释放），应阻塞或关中断。
- **多核** → 短临界区自旋有意义（持锁者可能正在另一核上即将释放）。

对应 rcore 的 `MutexSpin`（自旋）与 `MutexBlocking`（接调度器睡眠/唤醒）。本课信号量
`down` 的 `// TODO[a]` 阻塞式（记等待者）/ `// ELSE[b]` 自旋式（重试）正是这两条路线的缩影。

## 3. 单核「关中断」即可原子，为什么 SMP 必须用真原子？硬件的 DONE 位靠什么不被读到中间态？

单核内核里，并发只可能来自**中断打断当前执行流**。把中断一关，当前 CPU 就独占地跑完
读-改-写，没人能插进来，于是「关中断」就等价于原子（rcore 的 `UPIntrFreeCell` 即此思路）。

但到了 **SMP（多核）**，关中断只能挡住**本核**的中断，**另一个核**仍在同时跑、同时访问
同一块内存。两核各自「读 0 → +1 → 写 1」就会丢更新（本课的 NAIVE_RACE 演示）。所以必须用
**真正的原子指令**：RISC-V 的 `lr.sc`（load-reserved / store-conditional）或 `amoswap`，
它们借助**缓存一致性协议**（如 MESI）保证「读-改-写」对整个系统看起来不可分割——
`sc` 只有在保留期间没有别的核写过该地址才成功，否则失败重试。

硬件里那一个 `DONE` 位之所以不会被读到「中间态」，是因为它就是**一个触发器（1 bit 寄存器）**：
在时钟沿被 B 一次性地从 0 翻到 1，对 A 而言它要么是 0 要么是 1，**不存在半个 1**。
「原子」在硬件层面是天然的——单根线、单个 D 触发器、由同一个时钟沿定义其值。真正需要
小心的是**跨时钟域**或**多比特字段**：多 bit 一起变才会有「读到一半」的风险，这也正是
我们把「数据 RESULT」和「就绪 DONE」分开、并约定写序的原因。
