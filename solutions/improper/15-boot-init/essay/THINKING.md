# 15 · 思考题参考解（essay · 启动握手）

> 母题：**软件是硬件的开机咒语，链接顺序决定谁先念咒。**
> “必须先置位才能用”被压缩成 magic 解锁 → 合法 CLKDIV → EN → 轮询 READY 四步握手。

## 15.1 观察“坏掉的启动”：缺了哪一位？

`broken_boot` 跳过握手直接读 `DATA`，设备此刻 `unlocked=0 / clkdiv=0 / en=0 / ready=0`，
于是：

- `STATUS` 读回 `0x0E`：LOCKED(bit1) 因为没写 magic 解锁配置总线；BADCLK(bit2) 因为
  `CLKDIV=0` 非法；NOTEN(bit3) 因为没置 `CTRL.EN`；READY(bit0)=0 因为 PLL/时钟根本没起。
  四位一一对应“缺了哪一步握手”。
- `DATA` 读回 `0x0BADB007`：这是设备在“没就绪”时回吐的哨兵值（“BAD BOOT”的谐音），
  比读回 0 更有诊断价值——0 容易和“真的是 0 的数据”混淆，而 `0xBADB007` 一眼就知道
  “你在设备没醒时就用它了”。真实硬件里读未上电/未时钟的外设，总线常返回全 1、全 0
  或固定 pattern，本质同理：**读到的不是数据，是“设备没准备好”这件事本身。**

一句话：坏掉的启动不是“数据错”，是“时序/前置条件错”——你在咒语没念完时就开了门。

## 1. SBI/BootROM 替内核“置了哪些位”？为什么不放进内核自己做？

在 rcore 里，机器一上电跑的不是内核，而是 **BootROM → SBI（RustSBI/OpenSBI）**：它在
M 态把最基础的环境支起来——设置初始栈、把自己搬到合适位置、配置 PMP、把时钟/串口这类
“连打印都要用”的外设最小初始化、设置好中断委派，最后把控制权和 `a1=dtb`（设备树指针）
交给 S 态的内核入口。xv6 同理：`entry.S` 先建栈、再跳 `start`（设 M 态 CSR、委派、配时钟
中断），最后才 `mret` 进 `main`。

为什么这部分“通常不放进内核自己做”：

- **鸡生蛋问题**：内核要运行就得先有栈、有时钟、能取指；而这些恰恰是“要先置好的位”。
  让内核第一条指令去配自己赖以运行的环境，逻辑上闭不上环——必须有人在它之前先置位。
- **分层解耦 / 可移植**：SBI 把“板级差异”（哪块芯片、时钟怎么起、串口在哪）吃掉，给内核
  一个统一的 SBI 调用界面，内核就不必为每块板子改一遍。这正是“把硬件描述从内核源码里
  解耦出去”的同一思想（设备树也是）。
- **特权与安全**：M 态固件能做内核（S 态）做不到/不该做的事（PMP、安全启动验签）。

落到本课：SBI/BootROM 就是“链接到主程序之前”那段前置程序的真身——它替你把寄存器置好，
内核才敢假定“设备已就绪”。本实验用 `.init_array`/构造器在 `main` 之前跑 `boot_init`
来模拟这一层。

## 2. 为什么真实硬件常要“magic 解锁 + lock 寄存器”这种看似多余的握手？

因为关键寄存器一旦被**误写**，后果是“硬件层面的灾难”，而不是一句报错能挽回的：

- **看门狗**：喂狗/配置寄存器若被跑飞的指针或总线毛刺偶然写中，看门狗可能被关掉
  （系统死锁时不再复位）或被错误重配。STM32 的 IWDG 用 `0xCCCC/0x5555/0xAAAA` 这类
  key 序列、且配置位写完后**上锁**，就是要求“必须连续敲对几个 magic 才算数”，挡住单次
  偶然写。
- **Flash / 选项字节写保护**：擦写 Flash 要先写 `KEYR=0x45670123,0xCDEF89AB` 解锁，
  否则写操作被忽略。没有这道锁，一个野指针写到 Flash 控制器就能把固件擦了。
- **时钟配置 / JTAG 解锁**：时钟树寄存器、调试口解锁也常用 key+lock，避免“一次毛刺
  把主频配飞导致取指乱掉”，或“未授权就打开调试口”。

`magic + lock` 的价值在于**把“偶然单次写”变成“必须有意的多步序列”**：一个随机毛刺
几乎不可能恰好凑出 `0xB007C0DE` 这个 32 位 magic，更不可能再按顺序敲完后续步骤。这就是
看似多余的握手的意义——它不是给正常程序设障碍，而是给“异常写”设门槛。

## 3. `CLKDIV=0` 为何“执行错乱”？轮询 READY 的取舍？纯二进制如何保证前置程序先跑？

- **`CLKDIV=0` → 执行错乱**：分频为 0 等价于“没有有效时钟”。真实硬件里这对应 PLL 未锁定
  /时钟未起：没有稳定时钟，触发器不翻转、取指拿到的是亚稳态/乱码，CPU 或外设状态机就
  “跑飞”。本课用 BADCLK 位 + 永不 READY 如实再现：时钟没起，设备就永远到不了可用态。
- **轮询 READY 的取舍**：忙等 `while(!(STATUS&READY))` 简单、确定、无需中断基础设施，
  适合“启动早期还没有中断系统”的场景（PLL lock 通常几十微秒，忙等可接受）。代价是
  **白白烧 CPU**，且**没有超时**就会在“时钟永远起不来”（如 `CLKDIV=0`、晶振没焊好）时
  **死等卡死**。工业代码因此给轮询加超时 + 重试 + 报错降级；中断方式则省 CPU 但要求中断
  控制器已经可用——启动早期往往还没有，所以引导阶段普遍用忙等。
- **纯二进制（无 ELF 运行时）如何保证前置程序先跑**：ELF 下有 crt0 替你遍历 `.init_array`，
  构造器/`boot_init` 自动在 `main` 前执行；但裸机纯二进制没有这套运行时。这时靠
  **链接脚本**兜底：`linker.ld` 用 `ENTRY(_start)` 指定入口，把 boot/复位向量段用
  `KEEP(.boot.text*)` 排到镜像最前、定义 `__boot_start/__boot_end` 符号边界，`_start`
  里手写“建栈 → 调 boot_init → 跳 main”的序列。也就是说：**有运行时就用 `.init_array`，
  没运行时就用链接顺序+入口符号**，两条路都在落实同一句话——先置位，后开工。
