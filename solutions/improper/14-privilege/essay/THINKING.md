# 14 · 思考题参考解（essay · 特权级 = 连了几根线）

> 母题：**特权级不是护城河，是几根线。** `cur_priv` 不过是两个触发器；
> "有没有权限"是一个比较器 `cur_priv >= need` 拉出来的一根线；"切换特权"是给触发器写值；
> "开功能"是再点亮一个使能位。把这几根线看穿，M/S/U、`sret`、`sstatus.SPP` 就不再神秘。

## 1. 为什么"向下放权"能直接写寄存器，"向上提权"必须经 ECALL 这道门？

**对称性恰恰被故意打破。** 在硬件里，`DROP` 分支是"满足 `arg_priv <= cur_priv` 就把新值写进 `cur_priv` 触发器"——这是安全的：你只会把自己的权力**变小**，永远不可能因此越权。所以放权可以是一条普通指令，随手就写。

而"提权"若也允许直接写 `cur_priv`，整座保护体系当场崩塌：C 态（用户态）只要执行一句 `cur_priv = A`，就拿到了最高权限，特权级形同虚设。本实验的 `step` 里**根本没有"任意写 cur_priv 提权"这条路径**——想升回高权，唯一的门是 `ECALL`：它不是"用户决定去哪",而是**陷入到一个固定的、由高权代码掌管的入口**（真实硬件里 `cur_priv←M/S` 的同时 PC 被强制跳到 `mtvec/stvec`）。即"能提权，但落地点不由你选"。于是用户能做的只有"敲门求内核办事"，办什么、给不给、办完回哪，全由门后的内核裁决。

若真允许 C 态把 `cur_priv` 写成 A：任何用户程序都能关 MMU、改页表、读所有进程内存、改 `satp`/`stvec`——隔离、权限、安全全部失效，操作系统退化成"建议"。

这正解释了 **`sret`/`mret` 为什么只能"恢复"`SPP`/`MPP` 而不能"任意指定"目标特权**：返回时硬件把 `cur_priv` 写成进入陷入时**保存下来**的那个前态（我们的 `saved_priv`），而不是指令操作数给的任意值。配合"进入陷入时由硬件自动 `saved_priv←cur_priv`、PC←向量"，就形成一个闭环：**只能原路返回到来时的层级，不能借返回指令偷偷升级**。放权自由、提权受控、返回守恒——三句话就是特权机的全部安全直觉。

## 2. 特权级数量 ↔ 保存前态所需位宽 ↔ 陷入处理复杂度

真实 `sstatus.SPP` 只有 **1 位**，因为 S 态陷入只可能来自 S 或 U 两态，1 位足够区分"是否来自 S"。本实验三态（A/B/C）需要 **2 位** `saved_priv` 才能无损记下前态——这不是巧合：

- 要无损保存"来时的特权级"，`saved_priv` 的位宽至少是 `ceil(log2(特权级数))`。两态 1 位、三/四态 2 位、八态 3 位。位宽随特权级数**对数增长**。
- 但"陷入处理复杂度"增长得更快。每多一个特权级，就要回答更多问题：这级能访问哪些 CSR（每个 CSR 多一组权限比较线）、这级的陷入委托给谁（`medeleg/mideleg` 决定陷到 M 还是 S）、嵌套陷入时前态栈怎么存（单层 `saved_priv` 不够，要么禁止嵌套要么真的压栈）。线性多一级，**译码表、委托逻辑、状态保存**都要相应铺开。

> 用本实验的简化反推真实：我们只存**一层** `saved_priv`、没有委托、没有嵌套陷入栈——所以两位就够、一条 `trap` 线就够。真实 RISC-V 之所以位域那么多，正是因为它要支持委托链、嵌套、可屏蔽中断优先级。

**H 扩展再加一层虚拟化特权**（VS/VU）时，硬件多付出的不只是"前态再多一位"：它要再复制一整套 S 态的 CSR（`vsstatus/vsie/vstvec/vsepc/vsatp`…）、要做**两阶段地址翻译**（guest 虚拟→guest 物理→host 物理，TLB 与页表走查翻倍）、要新增 `hstatus`/陷入委托到 HS 的路径、要区分"陷到 VS 还是被 host 截获"。一句话：**多一层特权 = 多一套需要保存/切换/比较的硬件状态 + 多一层地址翻译**。位宽是对数代价，状态机和数据通路才是真正的主成本。

## 3. "开功能 = 置一个使能位"，为什么要做成"特权够 **且** 使能位亮"两道与门？

真实例子：**`satp` 开 MMU**。把 `satp.MODE` 从 `Bare` 写成 `Sv39`，地址翻译就从此开启——这就是"置一个使能位即开一类能力"。类似的还有 `mstatus.SUM`（允许 S 态访问 U 页）、`mstatus.MXR`（可执行页可读）、PMP 的 `lock` 位、各扩展的 `*enable`。

本实验的 `USEFEAT` 把判据写成 `cur_priv < arg_priv || feat_en == 0` 才陷入——等价于"通过 = `cur_priv >= arg_priv` **AND** `feat_en == 1`"两道与门。比"只看特权级"更安全、更灵活，原因有三：

1. **正交解耦权限与能力**。特权级回答"你是谁"，使能位回答"这个能力此刻开没开"。两者独立可组合：同一个 S 态，开了 `SUM` 就能碰用户页、没开就不能——不必为此再发明一个特权级。能力的开关粒度远细于特权级。
2. **默认安全 / 最小权限**。复位时使能位通常是 0（MMU 关、`SUM` 关）。即使你已经在足够高的特权级，只要还没"显式点亮"，能力就用不了。这把"有资格"和"已开启"分开，避免"一上电就什么都能干"。`satp=Bare` 时哪怕在 S 态也走物理地址，正是这个意义。
3. **可锁定 / 不可逆收紧**。PMP 的 `L`（lock）位一旦置上，连 M 态都不能再改这条表项直到复位——这是"使能位"比"特权级"更强的地方：它能表达"连最高特权都自我设限"的策略（secure boot 锁死配置、防固件被篡改后提权）。光靠特权级比较做不到"最高权也被挡"，必须靠一个独立的、置位即生效（甚至置位即焊死）的能力位。

一句话：**特权级是粗粒度的"身份门"，使能位是细粒度的"能力闸"，两道与门串起来，才能既按身份分层、又按能力逐项授权，还能在最高权之上再加一道自锁。**
