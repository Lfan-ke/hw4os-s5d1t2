## 1. 「文件名」的本质，以及为什么名字→inode 与 inode→数据块要分两层

(b) 里把 head 后 3 字节当 key，(c) 里把名字塞进 `DirEntry`——「文件名」本质上
只是一个**人类可读的标签**，它本身不存内容，只是「指向某个 inode 的一根线」。
真实数据（大小、块指针、权限、时间戳）全在 inode 里。

为什么要分两层（目录项「名字→inode」+ inode 表「inode→数据块」）而不是一张大哈希表：

- **多对一（硬链接）**：同一个 inode 可以挂多个名字。两层结构让「改名 / 加别名」
  只动目录项，不碰数据；一张「名字→数据」的大表做不到共享。
- **关注点分离**：目录是「命名空间」，inode 是「对象本体」。重命名是 O(1) 改一条
  目录项；移动文件不必搬数据。权限/大小等元数据只存一份（在 inode），不随名字复制。
- **目录本身也是文件**：目录 = 一串目录项组成的「文件」，于是可以递归套出树状层级，
  而哈希表是平的。
- 真实系统正是这样：xv6/easy-fs 的 `DirEntry{name, inode_no}` + `DiskInode`；
  Linux 的 dentry cache + inode。

## 2. mkfs / mount / dd 的职责边界，谁先谁后

- **mkfs（格式化）**：在一块「裸字节」上写出文件系统的**约定布局**——superblock、
  bitmap、inode 表、空根目录。它决定「这片字节以后按什么协议解释」。对应本课 `fs_mkfs`。
- **mount（挂载）**：把一个「已经是某种 fs 的块设备/镜像」**接到目录树的某个挂载点**，
  让内核用对应的 fs 驱动去解析它。它不改盘上字节，只改内核的「视图」。
- **dd（刷写）**：纯粹的**字节搬运**——把镜像一字节不差地拷到目标块设备。它完全不懂
  文件系统，只认地址和长度。

「格式化一个 img」与「把 img 刷进块设备」是两件独立的事：前者是**在内容里写协议**
（mkfs 作用于 img 的字节），后者是**把这堆字节搬到物理介质**（dd 作用于设备）。
解耦的好处是：可以离线在文件里造好整张盘，再一次性烧录。

真实磁盘上线顺序：先**分区表**（MBR/GPT，划出每个分区的 start_lba/count）→ 再在分区里
**mkfs**（建文件系统）→ 引导扇区/引导加载器最后写（它要知道分区与 fs 才能找到内核）。
即「先划地、再盖房、最后装门牌与门铃」。

## 3. RAM 块设备断电即失；要「掉电不丢」软硬各需补什么

我们的块设备是内存模型，(a) 的语义是「写完立即能读到」——这只是**内存可见性**，
不等于**持久性**。掉电后内存清零，已写文件全没。

- **软件侧**要补：写顺序与原子性保证。日志（journal）/写前日志（WAL）先把「打算做的
  改动」落到一块固定区域，崩溃后重放；写屏障 / `fsync`/`msync` 把页缓存真正下刷并
  等待设备确认；元数据更新顺序（先数据后指针）避免出现「指针指向垃圾」的中间态。
- **硬件侧**要补：非易失介质（Flash/NVMe/带电容的 DRAM）+ 明确的**写完成语义**——
  设备要能区分「已收下」与「已落到非易失介质」，并提供 FLUSH/FUA 让上层等待真正持久。

差别：(a) 的「写完立即能读到」只保证**同一次运行内的可见性**（内存语义）；持久化要求
跨「掉电」这条边界仍可见，这就需要介质本身不丢 + 一套「何时算真正写完」的契约。
内存语义里这条契约是隐式的（写完就完），持久化语义里它必须显式（flush + 完成确认）。
