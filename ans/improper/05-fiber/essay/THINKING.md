# 05-fiber 思考题参考答案（纤程 / 有栈协程）

## 1. 为什么协作式切换只需保存 callee-saved 寄存器？

RISC-V 调用约定把寄存器分两类：

- **caller-saved（临时寄存器）**：`ra` 之外的 `t0–t6`、`a0–a7`。调用方若在 `call` 之后还要用它们，必须自己在 `call` **之前**把它们溢出到栈、`call` **之后**再读回。
- **callee-saved（被调用者保存）**：`sp`、`s0–s11`。被调用的函数若要用它们，必须先保存、返回前恢复，对调用方而言「跨越 call 不变」。

`yield_now()`/`switch_ctx()` 本身就是一次**普通的函数调用**。在它被调用的那一刻，编译器已经在 call 点替我们把所有还活着的 caller-saved 值溢出到了当前栈帧里——它们的「家」在栈上，会随着我们切走/切回的那根栈一起被保留。因此上下文里**只需快照 callee-saved 子集**：`ra`（返回到哪）、`sp`（哪根栈）、`s0–s11`。这正是 rcore `TaskContext { ra, sp, s[12] }` 的 14×u64 布局，也是本实验 `switch_ctx` 用 `sd/ld` 搬运的全部内容。x86_64 同理：只存 `rbp/rbx/r12–r15/rsp` + 返回地址。

**关键洞见**：协作式（只在显式 `yield` 切换）才有这个便宜。抢占式（时钟中断随时打断）时，中断点的 caller-saved 还活着、编译器没替你溢出，就必须保存全部 GPRs（+CSR）——那才是内核线程切换昂贵的根源之一。

## 2. 换成纤程省了哪些内核开销？什么时候不划算？

省掉的内核态开销：

- **特权级穿越**：纤程切换全程在 **用户态** `U-mode`，没有 `ecall`/陷入 → 内核 → `sret` 的来回；不刷新流水线、不走陷入向量。
- **TLS / 线程局部存储重载**：内核切线程要换 `tp`(线程指针)、可能重载 TLS 段；N:1 绿色线程共享同一载体线程的 TLS，省了这步。
- **内核栈切换 + 内核数据结构**：不切 kernel stack、不更新 `current` TCB、不走内核调度器的就绪队列与锁。
- **调度器陷入**：让出是一次函数调用而非一次 trap。

不划算的场景：

- **某纤程长时间不 `yield`**：协作式没有抢占，它会**饿死**同一载体线程上的其他纤程（CPU 密集型循环最危险）。
- **阻塞式系统调用**：一个 `read()` 阻塞会卡住**整条载体线程**，连带其上所有纤程一起停摆（需要异步/非阻塞 I/O 或专门的 IO 线程来配合）。
- **真正需要并行**（多核同时跑）：N:1 纤程跑在单线程上没有并行，要并行得 M:N（多载体线程）或直接用内核线程。

## 3. 为什么「永不让出」的异步任务等价于顺序批处理？

单线程上没有抢占，切换的**唯一触发点就是 `yield`**（或阻塞让出）。如果一批任务体里全是纯计算、从不让出，那么调度器把第一个 `switch` 进去后，它会一口气跑到 `return` 才交还控制权——于是输出严格是 `task0_done → task1_done → task2_done`（本实验 `SEQ` 阶段）。这跟「拿一摞作业一本写完再写下一本」毫无区别：**毫无交错、毫无并行**，只是顺序批处理。

要让它们真正交错，**最少需要引入一个让出点**：在每个任务的「该等一下」的地方（模拟 I/O / 阻塞）插一句 `yield_now()`，调度器才有机会 round-robin 切到下一个，输出就变成 `0a 1a 2a 0b 1b 2b`（`INTERLEAVE` 阶段）。

与下一课「无栈协程」的异同：

- **相同**：都靠**协作式让出**推进，单线程、无抢占；不让出就退化为顺序。
- **不同**：本课**有栈**协程在让出处直接 `switch_ctx` 换整根栈，局部变量天然留在自己的栈上；无栈协程没有独立栈，`yield` 被编译成**状态机**，由外部反复 `poll`/`resume` 驱动，跨让出点存活的变量必须被编译器搬进状态机结构体里。前者「换栈」，后者「存字段」。

## 测量（选做）：切换成本与「绿色」何在

一次 `switch_ctx` 只搬 14 个寄存器、全在用户态、无 trap，量级是**几十个周期**；而一次穿内核的 `getpid()` 要 `ecall` 进 `S-mode`、存上下文、返回，量级是**几百到上千周期**。差距正来自：不穿内核、不存全部 GPRs/CSR、不重载 TLS。这就是绿色线程「绿」的来源。
