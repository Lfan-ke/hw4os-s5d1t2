# 09 思考题 · 稳定物理因果能否当 0/1 造计算机（参考答案）

## 1. 刘慈欣《三体》人列计算机

## 答

本质相同：人列计算机和我的硬件设备都建立在「稳定可复现的因果」之上——只要「举黑旗 → 下游举白旗」这条因果每次都成立，它就是一个可靠的逻辑门（非门）。0/1 不是数字本身，而是被我们约定解读的两种**稳定物理状态**：旗子的黑/白、寄存器里的高/低电平、环形设备里 r0/r1 的两个数。我的 `RingSum` 时序状态机靠时钟沿把「写入」这件事的因果钉死在每个 `posedge`，人列计算机靠传令兵把「门的输出」逐级传递——都是把因果离散化、对齐到拍。

不同：人列计算机的「因果」由人执行，速度极慢（传令以秒计）、可靠性极低（单兵会累、会走神）；硅电路的因果由物理（晶体管开关）保证，纳秒级、错误率极低。

- **单兵看错旗** = 一次**位翻转 / 软错误**（bit flip，如宇宙射线打翻一个 SRAM 单元），或门电路的瞬态故障。
- **传令延迟** = 信号的**门延迟 / 传播延迟（propagation delay）**，决定了最高时钟频率（关键路径）。
- **谁来当石英晶振** = 那个统一喊「下一拍！」的指挥（号令/鼓点）。它提供全局**时钟**，让所有门在同一拍对齐采样，避免有人快有人慢导致的竞争冒险——正对应我 tb 里的 `clk` 和 `posedge`。

## 2. 红石与晶振

## 答

一台最小计算机需要四类稳定物理因果：
1. **开关（逻辑/控制）**：能让一个信号去通断另一个信号——构成与/或/非门。
2. **放大（恢复/驱动）**：把衰减的信号重新拉满，使因果能级联很多级而不失真（晶体管、红石中继器）。
3. **存储（记忆）**：能把一个状态锁住直到下次改写（触发器/锁存器、我的 r0/r1 寄存器、红石 RS 锁存）。
4. **时钟（节拍）**：提供稳定固有频率给所有元件对齐（石英晶振的压电谐振）。

各种物理介质各能充当：
- **电力**：晶体管做开关+放大，电容/触发器做存储——这就是真实 CPU。
- **水力**：水流闸门做开关（流体逻辑），水塔水位做存储，滴漏/水钟做时钟。
- **气压**：气动阀做开关与放大（气动逻辑控制器至今用于易燃易爆场合），气罐压力做存储。
- **人力**：人列计算机——人举旗做开关，传令兵做放大/传递，记录板做存储，指挥喊拍做时钟。
- **磁力**：磁芯存储器（magnetic core）做存储，磁放大器做放大与开关。
- **铜线/光纤**：主要充当「连线」——传递因果（信号互连），光纤还能靠光开关做逻辑。

## 3. 一切皆文件

## 答

- **read 恒 1** 对应 `/dev/zero` 这类**常量源**（`/dev/zero` 是恒 0、`/dev/full` 读出也是恒 0；本课为了和 0 区分用恒 1，语义上是「读出固定常量、无尽供应」的源）。
- **write 恒 0**：我的约定里 write 返回「写了几个=0」表示数据被吞掉无存储，对应 `/dev/null`（写入永远成功、内容丢弃）。若 write 反过来**恒失败/报满**，那才是 `/dev/full`（写入返回 ENOSPC）。所以恒 1 读 ≈ `/dev/zero`，吞写 ≈ `/dev/null`。

为什么「一切皆文件」是强抽象：它把「存了字节的普通文件、键盘、屏幕、管道、网卡、块设备、内核状态」全部收敛到 `read/write`（再加 `open/close/ioctl`）这一组接口背后。调用者**不需要知道**对面是真存储还是硬件副作用——`cat` 既能读文件也能读 `/dev/zero` 还能读串口。这正是 rcore 的 `File` trait、xv6 的 `devsw`、Linux 的 `file_operations`：同一张函数指针表，背后可以是 inode、也可以是一段「硬件因果」。

串起来：本课的 MMIO 设备说明「读某个地址/写某个地址」本身就是一种带副作用的 `read/write`——`readl/writel` 用 `volatile` 裸指针去戳硬件寄存器，和我软件里调 `dev.read()/dev.write()` 形状一模一样。而第 01 课说「软件能做的硬件也能做」，本课补上后半句：「软件给硬件的接口，长得和给文件的接口一模一样」。于是三句话连成一条线：**因果可当 0/1 → 软硬同构 → 同构之上再罩一层 read/write 接口，就得到「设备文件」**。
