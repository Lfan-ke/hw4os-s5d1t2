## 1. 为什么无栈协程也叫「绿色线程」？省掉了哪些开销？

绿色线程 = 在**用户态**调度的轻量执行单元，调度器是一段普通用户代码，不陷入内核。
相比「陷入内核的线程切换」，合作式的无栈协程在用户态省掉了：

- **特权级切换**：协程切换是一次普通函数调用 / 一次 `poll`，不触发 trap、不走 `ecall`/中断门，
  省了 U↔S 模式来回与 `sret`。
- **内核栈**：不需要每次进内核时切到内核栈、保存完整 trap 帧。
- **TLB / 缓存抖动**：不切地址空间（同进程内），少了 TLB flush 与 cache 冷启动。
- **调度器锁 / 运行队列**：合作式让出，无需内核全局 runqueue 上的自旋锁与负载均衡。
- **TLS 切换**：同线程内推进，不换线程局部存储。

而「无栈」相对「有栈协程（05-fiber）」**还额外**省掉了：**每任务一根独立栈**的内存与预留。
有栈协程必须给每个任务预留一段栈（哪怕只用几十字节也常按 KB 预留以防溢出）；无栈协程把
「跨让出点存活的局部」编码进一个**几十字节的状态结构体**，N 个任务就是 N 个小结构体，
海量并发时内存占用是数量级的差距。

一句话：**有栈协程换的是栈指针，无栈协程换的是状态号**。

## 2. 无栈 vs 有栈：各自的「不能」与「自然」

- **无栈为什么不能从任意深的调用栈中间 yield？**
  无栈协程是「编译器/宏把一段顺序代码掰成的状态机」，让出点必须在**这台状态机自己的函数体里**
  显式出现（`.await` / `PT_YIELD`）。如果你在一个普通深层函数里想挂起，它的栈帧不会被保存——
  因为根本没有栈被保存。于是「能挂起」这件事会沿调用链**传染**：被调用者是 `async`，调用者也得
  `async`，一路染上去。这就是**函数染色 / red-blue function** 问题：`async` 函数是「红色」，
  普通函数是「蓝色」，红色只能在红色里 `.await`。
- **有栈为什么内存更大、却编程模型更自然？**
  有栈协程在挂起时**整根调用栈连同所有栈帧原样保存**（换 SP 即可），恢复时接着跑。
  因此可以在**任意深度、任意第三方库调用内部**直接 yield，代码看起来就是普通同步代码，无需染色。
  代价是每任务一根栈 → 内存更大、且需处理栈溢出 / 栈增长。
- **场景**：
  - 适合无栈：**海量轻量连接**（百万级 socket 的事件循环 / embassy / tokio）——每连接只占几十字节状态，
    且让出点都在自己的协议处理函数里。
  - 适合有栈：**需要在深层第三方库调用里挂起**（如某个不可改的同步风格库中途要让出），
    或希望「写起来就是普通函数」的场景（Go goroutine、Lua coroutine）。

## 3. 「无栈协程 = 状态机 = 硬件 FSM」是同一台机器吗？

是。把三者并排：
- **06.1 手写 enum 状态机**：状态号 `i` + `poll` 里的 `switch`/分支，跨让出点的局部塞进结构体。
- **06.4 编译器生成的 Future**：`async fn` 被编译器**自动掰成**等价的状态机，`acc`/`i` 被塞进
  生成的匿名 Future 结构体——与你手写的逐位同构，只是「谁来写」从你变成了编译器。
- **硬件 FSM**（01 课的回响）：同一张状态转移表落成时序逻辑，**一个时钟沿 = 一次 poll**。

这正呼应第 01 课「软件能做的，硬件也能做」：同一台状态机，可以由你手写、由 C 预处理器宏生成、
由 Rust 编译器生成、或由一块芯片流片成时序电路。若让芯片「流片成一个协程」：
- `Pending` ↔ 「还没好」的信号：`valid=1` 吐让出值、但 `done=0`（下个时钟沿继续推进）；
- `Ready` ↔ `done=1`（终值有效，状态机停在终态）。
执行器的「轮询」就是给它**喂时钟**；reactor 的「唤醒」就是给它**拉高使能/事件线**。
