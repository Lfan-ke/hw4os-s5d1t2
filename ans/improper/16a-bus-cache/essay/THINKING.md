# 16a · 总线与缓存 思考题（参考答案）

## 题：用 §2.2 地址图 + §2.3 时间模型讲清：(1) 仲裁=地址译码 + cache 在“类内存”区为何成立；(2) 突发账的 SPEEDUP；(3) sensor/switchdev 两个直通反例，并收束“MMIO 必须 UNCACHED”。

## 答

### 1. 仲裁 = 地址区间译码；cache 暂存只对“类内存”区成立

把“总线 / 互连 / 仲裁器”这些看似高深的词祛魅，留下的内核就一句话：**按地址区间查表选设备**。
拿 §2.2 的地址图：

| 区间 | 设备 | 可缓存 |
| :-- | :-- | :-- |
| `0x4000_0000..0x4000_1000` | `regdev`（类内存） | √ |
| `0x4001_0000..0x4001_0010` | `sensor` | × |
| `0x4002_0000..0x4002_0010` | `switchdev` | × |
| else | `BUS_ERR` | - |

仲裁器就是对每段做 `addr >= base && addr < end` 的比较，命中谁就把请求路由给谁，全落空就是总线错误。
硬件里它是纯组合逻辑（`assign sel_x = (addr>=BASE)&&(addr<END)`，再 `bus_err = ~(|sel)`），软件里它是
`if / else if` 链 - **同一台译码器，两种语法外壳**。四变体跑同一组 8 个地址、对照同一张期望路由表，
打印逐位一致的 `ARB_PASS`，证明“仲裁”并不神秘。

cache 为什么能在 `regdev` 上成立、却**不能**在 `sensor`/`switchdev` 上成立？因为 cache 暂存隐含一个假设：
**“同一地址，这次读到什么，下次读还是什么（除非我自己写过）”** - 即**存储语义 / 幂等读**。`regdev` 是被内存背书的
寄存器文件，满足这个假设，所以首读 `miss` 取设备、之后 `hit` 命中缓存，既省一次设备往返、读值又始终一致。
这就是“类内存可缓存”的全部含义。

### 2. 突发摊薄握手：BYTE_T=4.8 vs BURST_T=0.2，SPEEDUP=24

§2.3 的时间模型：**单次总线握手 = 0.2s**（建立地址/选通/应答的固定开销），传输本身忽略。于是同样搬 24 字节：

- **逐字节**：每个字节单独走一次握手 → `24 次握手 × 0.2s = 4.8s`（`BYTE_T=4.8`）。
- **突发**（`MODE=burst` 且请求 ≥3 单位）：一次握手把整块 24B 搬完 → `1 × 0.2s = 0.2s`（`BURST_T=0.2`）。

`SPEEDUP = BYTE_T / BURST_T = 4.8 / 0.2 = 24`。本质：**握手是固定开销，把它摊到更长的连续传输上，单位数据的开销趋于零** - 
这正是真实 DRAM 突发、cache line 填充、DMA scatter-gather 一次发起、批量搬运的同一笔账。代码里 C 用 `nanosleep`、
Rust 用 `thread::sleep` 真实睡眠 0.2s/次，并用单调时钟测量兜底，确保 `SPEEDUP` 来自实际运行而非硬编码。

### 3. 两个直通反例 - 缓存即错

cache 成立的前提（存储语义 / 幂等读 / 写只改自己）一旦破坏，缓存就从“优化”变成“缺陷之源”：

- **`sensor`：读有“时间副作用”。** 它的 `TEMP` 每 tick 变（每次读返回新值）。若把它当可缓存：第一次读 `t=1`
  进缓存，第二次读命中缓存仍得 `1` - 读到**过时值** `STALE`。只有**直通**（每次真正访问设备）才拿到 `FRESH=2`。
  因此“读不幂等”的设备不能缓存读。
- **`switchdev`：写有副作用。** 写它 = 翻转设备物理状态。若把写“吸收进缓存”（写合并 / 写回未刷）：
  缓存里值变了，**设备却没收到这次写**，副作用没下达 - `MISSED_SIDEEFFECT`。只有**直通**写才真的
  `SWITCHED`（state 翻转）。因此“写有副作用”的设备不能缓存写、不能写合并。

### 4. 收束：非存储语义的 MMIO 必须 UNCACHED - 这就是寄存器要 volatile/fence 的根因

`sensor`/`switchdev` 不是内存，是**设备**：读可能推进状态、写会触发动作。对它们，编译器/缓存/CPU 任何
“看起来等价”的省事优化（缓存命中、读合并、写合并、乱序、消除“多余”的重复读写）都会改变设备实际看到的
**访问序列**，从而改变行为。所以这类地址必须标成 **`UNCACHED`**（不可缓存 / 直通），且程序侧要用
`volatile`（禁优化删改/合并）+ `fence`（管可见性与顺序）逐次、保序地把每一次访问**原样**送到设备。

这正是 16b 里“寄存器为什么要 `volatile`、C 为什么要 `fence rw,rw`”的根因，也是 RISC-V PMA / x86 MTRR/PAT
把 MMIO 区标为 uncached-device 的现实依据。一句话收束：**`regdev` 是内存的语法外壳，可缓存可突发；
`sensor`/`switchdev` 是设备的真身，必须直通 - cache 的边界，就是“存储语义”的边界。**
