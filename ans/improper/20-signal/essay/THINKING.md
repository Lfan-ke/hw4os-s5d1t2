# 20-signal 思考题参考答案（essay 变体）

## 1. 什么是「异步事件」？信号为什么需要 handler 表 + pending + mask 这套机制？

**异步**指的是：事件发生的时机与当前执行流**无关**、随时可能插进来。进程正老老实实算着
自己的代码，外面（内核、另一个进程、硬件）忽然要它「立刻注意一下某件事」——这就是信号。
它不像函数调用（你主动去调），而像有人随时拍你肩膀。

正因为「随时」，才需要这三件套：
- **handler 表**：事先登记好「拍肩膀时我该做什么」（注册回调），否则来了也不知如何反应
  （走默认动作：忽略 / 终止 / dump）。
- **pending 位集**：有时我**正忙、不能被打断**（临界区、或正在处理别的信号），信号来了
  又不能丢，就先**挂起**记一笔，等我腾出手再处理。这就是「投递不出去先入队」。
- **mask 位集**：我主动声明「这段时间别拿某些信号烦我」。被屏蔽的信号只能进 pending，
  等我 unmask 再**补投递**。这是进程对异步性的**主动节流**。

一句话：信号 = 「软件版中断」。pending/mask 就是软件给异步事件造的「缓冲 + 闸门」。

## 2. 什么是 async-signal-safe（异步信号安全）？为什么 handler 里能做的事极其有限？

handler 是**异步插进来**的：它可能在主程序执行到**任意一条指令**的中间被调用——包括主程序
**正持有某把锁、或 malloc 改到一半内部链表**的时刻。如果 handler 这时也去 `malloc`/`printf`
（它们内部也加锁、也动同一份全局数据结构），就会**自我死锁**或**破坏不变量**。

所以 POSIX 规定：handler 里只能调用一小撮 **async-signal-safe** 的函数（如 `write`、
`_exit`、`signal`、若干 syscall 包装），**不能**调用 `malloc`/`free`/`printf`/`stdio` 这类
**不可重入**的函数。常见的安全写法是：handler 里只做一件极小的事——比如把一个
`volatile sig_atomic_t` 标志置 1（或往 `pipe` 写一个字节，即「self-pipe trick」），真正的
处理留给主循环。本实验的 `h_deliver` 就只改一个标志位，正是这个范式的缩影。

「可重入」与此同源：handler 运行中又来同号信号，若直接递归进入 handler，而 handler 用了
非可重入的资源，就会踩自己的脚。本实验用 `in_handler` 守卫把同号信号合并进 pending、
**绝不递归重入**，就是在软件层模拟标准信号的「运行期间自动屏蔽本信号」。

## 3. `signal()` 与 `sigaction()` 有什么区别？为什么现代代码该用后者？

- `signal()`：古老、语义在不同 Unix 上**不一致**（有的会在 handler 一进入就把处置重置回
  默认 `SIG_DFL`——所谓「System V 一次性」语义，必须在 handler 里重新注册，期间还有竞态
  窗口）；能表达的东西也少。
- `sigaction()`：语义**明确且可移植**。能精确指定：
  - 处理期间额外屏蔽哪些信号（`sa_mask`）；
  - 标志位 `sa_flags`：`SA_RESTART`（被信号打断的慢系统调用自动重启，而非返回 `EINTR`）、
    `SA_SIGINFO`（拿到 `siginfo_t`，知道是谁、为何发来、附带的值）、`SA_NODEFER`
    （处理期间不自动屏蔽本信号）、`SA_RESETHAND`（一次性）等；
  - 处置**不会**被悄悄重置，没有重注册竞态。

所以现代代码**一律用 `sigaction`**。本实验「handler 运行期间本信号被自动合并/不重入」对应
`sigaction` 默认行为（未设 `SA_NODEFER`，处理期间隐式把本信号加进屏蔽）。

## 4. 「标准信号」与「实时信号」在排队上有何本质区别？本实验建模了哪一种？

- **标准信号**（1..31，如 `SIGINT`）：pending 是**一个位**。屏蔽期间同号信号来 100 次，
  解屏蔽后也**只投递一次**——多余的被**合并/丢弃**，且**不保证顺序**。本实验的 pending 用
  `u32` 位集、`raise` 多次只置同一位，建模的正是这种「合并、丢重复」语义（REENTRANT 子题
  里连发 3 次只补投递 1 次）。
- **实时信号**（`SIGRTMIN`..`SIGRTMAX`）：**逐个排队**，来 100 次就投递 100 次，按号大小
  与到达顺序有确定优先级，还能用 `sigqueue` **携带一个数据值**（`siginfo_t.si_value`）。

要把本模型升级成实时信号，就把 pending 从「位集」换成「每号一个 FIFO 队列（含携带值）」，
`raise` 改成入队、补投递改成逐个出队即可。

## 5. 信号与硬件中断有什么类比？又有哪些关键不同？

**相似（信号 ≈ 用户态的中断）**：
- 都是**异步**打断当前控制流，跳到一段**预先登记的处理例程**（handler ↔ 中断向量表里的 ISR）。
- 都有**屏蔽**机制（`mask` ↔ CPU 的中断使能位 / `mstatus.MIE` / PLIC 屏蔽）。
- 都有**挂起**概念（pending 位集 ↔ `mip`/中断控制器里的 pending 位）。
- handler/ISR 都要**短、可重入、别在里面干重活**（async-signal-safe ↔ ISR 只置标志、把活
  丢给下半部 / 软中断 / 工作队列）。

**关键不同**：
- **触发主体与层次**：硬件中断由**硬件电路**在指令边界注入、运行在**特权态**、由 CPU/中断
  控制器（PLIC/CLINT/APIC）裁决；信号是**内核在返回用户态前**「软件投递」给进程的，跑在
  **用户态**，是内核搭在中断之上的**更高层抽象**。
- **投递时机**：中断几乎在硬件允许的瞬间就打断；信号通常在进程**下一次从内核返回用户态**
  时才被送达（所以会有「积压再统一处理」的窗口，正对应 pending）。
- **粒度与排队**：中断有硬件优先级与精确的 pending 线；标准信号则是**合并的一个位**、不排队
  （见上题）。

可以说：本实验在用户态用 `handlers/pending/mask` 重演了一遍中断控制器的心智模型——
「登记 ISR、置 pending、按 mask 闸门、择机投递」，硬件那套的软件投影。
