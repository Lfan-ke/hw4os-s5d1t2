# S08b 思考题（参考答案）

## Q1. `mmap` 有哪些用途？匿名映射 / 文件映射 / 共享内存各是什么？

`mmap` 把「一段虚拟地址」与「某种后备存储」建立映射关系，是用户态拿到大块地址空间的统一入口：

- **匿名映射 (anonymous)**：没有文件后备，映射的页首次访问时补**零帧**。`malloc` 大块内存、进程堆/栈
  扩展、`calloc` 都走它。本实验实现的就是匿名映射——`vma_handle_fault` 命中后 `frame_alloc()` 给零帧。
- **文件映射 (file-backed)**：把文件某段映进地址空间，VMA 额外记 `{文件, 偏移}`；缺页时不是给零帧，
  而是从文件系统(S07/VFS)把对应页读进来。可执行文件加载、`mmap` 读大文件都靠它——读文件像访问内存。
- **共享内存 (shared)**：多个进程各自的 VMA 指向**同一组物理帧**；一方写另一方立刻看到，是进程间
  通信(IPC)的快路径。私有映射(MAP_PRIVATE)则配合 CoW，写时各自分裂出私有页。

一句话：`mmap` 用「VMA + 缺页补页」把文件、匿名内存、共享段统一成「访问虚拟地址」这一种动作。

## Q2. 按需调页 (demand paging) 为什么省内存、还能加快启动？对照 S05c 的预先全映射。

- **S05c（eager，预先全映射）**：开机就 `map_one` 把区间每一页都映射到物理帧。哪怕程序根本不碰，
  物理帧也已经占住了。映射 N 页就立刻吃 N 页物理内存、跑 N 次建表。
- **S08b（lazy，按需调页）**：`mmap` 只在 VMA 表写一条记录，**零物理帧**。程序碰哪页才补哪页。

省内存：进程常申请远大于实际使用的地址空间（稀疏数组、保守预留、大文件只读开头）。按需调页让
「申请」和「占用物理内存」解耦——未触碰的页一帧不费。本实验 `LAZY_PASS` 就是证据：mmap 4 页、
只碰 2 页，物理帧恰好只多用 2 个，另外 2 页页表里仍是空的。

加快启动：程序/库可以「映射进来」就开始跑，不必等所有页都读盘/清零完成；用到的页才逐个换入，
启动延迟摊薄到运行期。大程序「秒开」很大程度靠它。

## Q3. 为什么说缺页 (page fault) 是机制而不是错误？本实验缺页处理器做了什么？

缺页只是硬件 MMU 在「页表里没有有效叶 PTE / 权限不符」时给 OS 的一个**回调点**，OS 完全可以
在回调里把缺的东西补上、然后让出错指令**原地重跑成功**——对程序完全透明，它根本不知道刚缺过页。

本实验缺页处理器 `vma_handle_fault` 的动作：
1. 从 `stval` 取出出错虚拟地址；
2. `vma_find` 查它是否落在某个已登记的 VMA：
   - **命中** → `frame_alloc()` 取零帧、`map_one` 把这一页映进页表、`sfence.vma` 刷 TLB、返回 1；
     trap 看到返回 1 就**不前移 `sepc`**，`sret` 后 CPU 重执行刚才那条 load/store，此刻页已就位、成功。
   - **未命中** → 返回 0，这才是真错误（野指针 / 已 munmap），trap 记录并跳过指令安全恢复。

「补页 + 重执行」是缺页作为机制的精髓——只有 vma_find 失败的那次，缺页才退化为「错误」。

## Q4. 写时复制 (CoW) 也靠缺页。它和本实验的按需补页有什么异同？

**相同**：都把工作推迟到「真正访问」那一刻，都靠同一套缺页钩子触发，命中后让出错指令重执行。

**不同**在「触发条件」和「命中后干什么」：
- 本实验（按需补页）：触发是**叶 PTE 不存在**（首次访问）；命中后给一个**新零帧**并映射。
- CoW：`fork` 后父子**共享**同一批物理页，但页表把它们的 `W` 位**清掉**；任一方**写**时触发 store
  缺页（页在、但无写权限）；命中后**复制一份私有页**、把写者的 PTE 指向副本并加回 `W`，再放行。
  这样 `fork` 不必立刻拷贝整个地址空间——只有被写的页才分裂，`fork` 因此极快。

可见 mmap 的按需调页、CoW、栈自动增长、文件映射，都是「VMA 描述合法区域 + 缺页时按策略补页」
这一个框架的不同实例；区别只在缺页命中后执行哪种补救动作。这正是 S05c 页表机制之上长出的真正威力。
