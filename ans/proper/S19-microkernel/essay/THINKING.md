# S19 思考题（参考答案）

## 1. 宏内核与微内核在“服务放哪、怎么调用”上的根本区别是什么？各自的代价与收益？

**宏内核**把文件、网络、驱动等服务**全放进内核态**，与内核同处一个地址空间。客户调用服务就是一次普通的**函数调用**——`call` 进去、`ret` 回来，参数走寄存器/栈，零拷贝、零上下文切换。本课 `macro.c` 里 `svc_create`/`svc_read` 就是直接 call，`hops=0`。**收益**是快、简单；**代价**是没有隔离：任一服务的一个野指针就能踩坏内核任意数据、拖垮整个系统，且服务越堆越多、内核越来越大越难维护。Linux 是典型宏内核。

**微内核**只把最小机制（地址空间、调度、**IPC**）留在内核，把文件/驱动等服务**赶到用户态变成独立服务进程**。客户要用服务，不能直接 call（不在同一地址空间、特权级也不同），只能**发消息**：请求经 IPC 送进服务进程、服务处理完把结果经 IPC 送回。本课 `micro.c` 里一条请求要 `send→recv→处理→send→recv` 共 4 跳，8 条请求 `hops=32`。**收益**是隔离与可靠：服务崩了内核不崩、可单独重启，最小可信基（TCB）小、易形式化验证（seL4）；**代价**是每次调用都要 IPC——陷入、消息拷贝、两次以上上下文切换，比一条 `call` 贵得多。QNX/seL4/Mach 是典型微内核。

一句话：宏内核拿**隔离性**换**性能**，微内核拿**性能**换**隔离性与可靠性**。本课的 `hops=0` vs `hops=32` 就是这笔交易的定量缩影。

## 2. 本课用“IPC 跳数”度量微内核开销，真实系统里这笔开销具体花在哪？为什么微内核的成败常系于 IPC 快慢？

本课的“跳”是把真实开销抽象成了“消息搬运次数”。真实系统里，一次微内核服务调用的开销具体是：

1. **特权级切换 / 陷入**：客户在 U 态执行 IPC 发送，要 `ecall` 陷入内核（S/M 态），内核保存上下文、查权能/端点、再把消息投递给目标进程——一来一回至少两次陷入。
2. **上下文切换**：客户进程→服务进程→回客户进程，至少两次完整的地址空间切换。切地址空间意味着**换页表（satp）+ 刷 TLB**，TLB 失效后续访存全是 miss，这往往是最大的隐性成本。
3. **消息拷贝**：请求/应答数据要从客户地址空间拷到内核再拷到服务（或反之），长消息拷贝成本随长度线性增长——所以微内核偏爱**短消息 + 共享内存大块数据**（消息只传“门铃”，数据走 shared region，正是 S14 共享内存握手的心智）。
4. **调度延迟**：目标服务进程不一定立刻上 CPU。

宏内核一条 `call` 这些全省了。所以微内核的**全部性能命脉系于 IPC 有多快**：Mach 早期因 IPC 慢被诟病“微内核太慢”；Liedtke 的 L4 把一次 IPC 优化到几百个周期（精简寄存器传递、直接进程切换、避免不必要拷贝），才证明“微内核可以不慢”。这也是为什么微内核论文里 IPC 往返延迟是头号 benchmark——它就是微内核的“每次系统调用税率”。

## 3. 可插拔驱动注册表（`driver_register`/`driver_find`）为驱动系统收了什么尾？它和宏/微内核形态怎么结合？

驱动注册表把“**有哪些驱动**”与“**内核怎么调用驱动**”解耦：每个驱动只需把自己的 `{name, ops}` 登记进表，内核统一按名字（真实系统按设备类型/总线匹配）查找并通过函数指针派发。**收益**是开闭原则——新增一类设备只写一个驱动 + 一行注册，内核分发代码一行不改；卸载就是清表项。这正是 Linux `struct file_operations`/驱动模型、设备树 `compatible` 匹配的最小骨架，也是本课给 S6 驱动模型收的尾：从“硬编码调用某个固定驱动”进化到“运行时可插拔的驱动表”。

它和两种形态都能结合，但姿态不同：

- **宏内核**：驱动注册表在内核态，驱动是内核模块，`driver_find(...)->read(...)` 就是一次内核内的间接函数调用——快，但驱动崩了崩内核（Linux 一个坏驱动能 panic 整机）。
- **微内核**：每个驱动是一个**用户态驱动进程**，“注册”是向内核/名字服务登记一个 **IPC 端点**，`driver_find` 拿到的是端点而非函数指针，“调用”变成给该端点**发消息**（就是本课 MICRO 路径那套请求/应答）。好处是坏驱动只崩自己、可重启（这正是微内核做高可靠/实时系统的卖点）；代价依旧是每次 I/O 都付 IPC 税。

所以本课三段连起来讲了一个完整故事：**同一个服务**（含驱动）既可像 MACRO 那样直接 call（宏内核、快、不隔离），也可像 MICRO 那样经 IPC 端点调用（微内核、隔离、有开销）；而**注册表**就是把“服务/驱动”做成可插拔单元、让两种形态都能优雅扩展的那块拼图。
