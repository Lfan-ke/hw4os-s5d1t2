# S09b · 真工具链链接 思考题（参考答案）

> 判据：答案非空且命中关键字（如 `ET_REL` / `程序头` / `INTERP` / `重定位` / `共享` /
> `拷贝` / `GOT` / `PC 相对` / `ASLR`）即过 `ESSAY_PASS`。

## 1. `gcc -c` 出的 `.o` 即便 `chmod +x` 也跑不了，根因是什么？

`.o` 的 ELF 类型是 **`ET_REL`（可重定位目标）**，不是可执行：它**只有节（section）、没有程序头
（program header）**，于是没有 `PT_LOAD`（内核不知道把哪段映射到哪）、没有 `PT_INTERP`（动态可执行才有
的解释器路径）、入口 `_start` 也不存在；而且 `printf`/`puts` 这类外部符号还是 **`U`（未定义）**、地址没经
**重定位**回填。内核 `execve` 校验到它不是 `ET_EXEC`/`ET_DYN`、没有可加载段，直接拒绝 → `Exec format error`
（exit 126）。所以门槛是**链接**：必须用 `ld` 把它（+crt 启动文件+libc）链成 `ET_EXEC` 或 PIE(`ET_DYN`)、
补上程序头/入口/重定位，才能跑。

## 2. `-static` 比动态大 ~49 倍，省下的去哪了？静/动各自的取舍？

省下的 ~769KB 就是**整份 glibc 的代码**：静态版把它**拷进**可执行（~785KB，各塞一份），动态版**不含**、
只留对 `libc.so.6` 的**名字引用 + 重定位项**（~16KB）。运行动态版时这些代码来自磁盘的 `libc.so.6`，由
`ld.so` `mmap` 进来，而且**多进程共享**物理内存里的同一份只读代码页（内核按 inode 的 page cache）。
取舍：**静态** = 单文件、无依赖、可移植、启动快，但**费空间**（每程序各塞一份）、修 libc bug 要**逐个重编**；
**动态** = **省空间**（一份共享）、换一个 `.so` 就**全体打补丁/升级**、支持 `LD_PRELOAD` 注入，但依赖 `.so` 在位、
启动要 `ld.so` 解析（略慢）。这正是 03b 模型里 `static_total_space` vs `dyn_total_space` 的真实版。

## 3. RISC-V `puts@plt` 的 `auipc/ld/jalr` 三条各做什么？为何必须经 GOT 间接？

- `auipc t3, off_hi`：**算地址**——用 PC 相对把 `puts` 对应 **GOT 项的地址**的高 20 位拼进 `t3`。
- `ld t3, off_lo(t3)`：**装入真实地址**——从 GOT 项**读出** `puts` 的真实地址（首次是解析器入口，`ld.so`
  回填后是 `puts` 真地址）。
- `jalr t1, t3`：**间接跳**——跳到 `t3` 指的地址、把返回地址存 `t1`（供解析器反推是哪个 PLT 项）。

为何必须经 GOT 而非一条 `jal puts`：① **链接期 `puts` 真实地址未知**（在 `libc.so` 里、运行时才定）；
② `jal` 是 **PC 相对、范围仅 ±1MB**，够不到任意加载的库；③ **PIC/ASLR** 要求代码段只读、不能把会变的
绝对地址写死在指令里——于是把"会变的地址"集中到**可写的 GOT**，代码只引用 GOT 项（相对固定偏移），
由 `ld.so` 运行时把真实地址**回填**进 GOT。这就是 03b 里"GOT 槽 + resolve 回填"的真实指令级形态。
