# F3-exokernel 思考题参考答案（essay 变体）

## 1. 「内核当裁判，不当独裁者」是什么意思？外核为什么这么设计？代价是什么？

宏内核（Linux/xv6）是「独裁者」：它**强行**规定一切应用都用同一套抽象——文件就是
字节流、内存就是 `mmap` 的虚拟页、调度就是它那一种策略。问题在于：这些抽象本身有
固定开销，而且**不同应用想要的抽象不同**。数据库想自己管理页缓存与磁盘布局（它比内核
更懂访问模式），GC 语言想自己管页换出，高性能网络想绕过内核协议栈直接收发帧。被独裁者
塞一套抽象，反而是性能与灵活性的枷锁。

外核（Engler & Kaashoek, SOSP'95）改当「裁判」：内核**只**做两件事——
**安全多路复用裸资源**（把物理页 / 磁盘块 / CPU 时间片 / 网卡帧发给不同应用）+
**保护检查**（裁定边界、不重叠、谁拥有谁能用），**绝不规定这些资源该被当成什么抽象**。
抽象（文件系统、虚拟内存、进程、网络栈）全部下放到应用自带的 **libOS** 用户态库里实现。
本实验的 `exo_alloc` 就是这个「裁判」：它只校验「越界 / 重叠」，发放块的归属句柄，
从不关心 libA 把这些块当顺序文件、还是 libB 当分块文件——那是 libOS 的自由。

代价：(1) **复杂度转移**——抽象没消失，只是从内核搬到每个应用，应用/libOS 作者要自己
写 fs/vm，门槛高；(2) **保护与灵活的张力**——内核既然不懂资源语义，要安全地「收回」
已发放资源（revoke）就更难，外核为此引入 secure binding / visible revocation /
abort protocol 等机制；(3) **生态**——通用应用没人愿意自带 libOS，所以外核 30 年没成
主流。但其思想活在 Unikernel（libOS+app 编一起）、DPDK（用户态绕内核收发包）、
eBPF（把策略下放给应用注入）里。

## 2. Aegis / Xok / jos 怎么把 OS 抽象交给 libOS？举本实验的例子。

MIT 的 Aegis（1995，第一个外核）与 Xok（1997）把硬件资源以「能被应用直接命名/操作」的
形式暴露：物理页、磁盘块、TLB 表项、网卡数据包过滤器。配套的 libOS 叫 **ExOS**，在用户态
实现了完整的 UNIX 抽象（fork/exec/pipe/fs）。关键是 ExOS 只是一个**库**，应用可以替换它、
或自带一个**专用** libOS。Xok 的 C-FFS 文件系统就是一个 libOS 级 fs，不同应用能跑不同的
磁盘布局策略。

教学外核 **jos**（6.828 旧 lab 路线）把这点讲得最直白：内核只提供
`sys_page_alloc(envid, va, perm)` —— 给你一个**物理页**并 map 到指定虚拟地址，
**但不提供 `malloc` / `mmap` / 堆**；`sys_exofork` 给你一个空壳环境，fork 的「写时复制」
语义由用户态 lib（`lib/fork.c`）用页权限自己拼出来；文件系统是 lab5 的用户态 fs server
（`fs/`），内核根本不认识「文件」。「内核给页不给堆、给块不给文件系统」正是外核精神。

本实验缩影了这一点：`exo_alloc` 等价于「内核发块」，而 `LibFs` 等价于 libOS。
**同一份裸资源**（块 6..12）发给 libB 后，libB 用「从尾倒序挑块」的 `libb_place` 策略
把文件铺成 `[11,10]`；而 libA 在它的块 0..6 上用「顺序升序」铺成 `[0,1]`。两种
**文件抽象/磁盘布局完全不同**，却都能正确读回同一份字节——这就是「内核只发资源、抽象交给
libOS」的本质：**机制（发块、查边界）在内核，策略（怎么布局成文件）在应用**。

## 3. 外核与 SASOS（单地址空间 OS）有何本质区别？

两者都走内核的「减法」路线，但减的维度不同：

| 维度 | 外核 (Aegis/Xok/jos) | SASOS (Opal/Mungi/BareMetal) |
| :-- | :-- | :-- |
| 地址空间 | **多个**——MMU 隔离不同 libOS/应用 | **单一**——全系统共享一个虚拟地址空间，无切换无 TLB flush |
| 隔离/保护 | **软硬结合**：MMU + capability + secure binding，互不信任 | **几乎不隔离**：信任所有代码（或靠语言/能力做软隔离）|
| 设计目标 | **灵活**：每应用自带最合身的 OS 抽象 | **极致性能**：消灭地址空间切换、零拷贝、零 TLB flush |
| 应用形态 | 多个互不信任的 libOS 共存 | 单/多 app 共享同一空间 |

一句话：**外核要的是「灵活」（多 libOS、各取所需的抽象，靠 MMU 保护彼此），SASOS 要的是
「快」（单地址空间、零切换，靠牺牲隔离换性能）**。本实验给 libA、libB 各自一段**不重叠**的
块并校验边界，正是外核「多方共存 + 保护检查」的味道（虽然 demo 没真上 MMU，
而是用块归属表模拟那道保护边界）；若是 SASOS，两者会在同一空间里裸跑、不设这道边界。

两条路线在现代殊途同归：外核思想 → Unikernel / DPDK / eBPF（把机制留给内核、策略给应用）；
SASOS 思想 → Unikernel / Serverless（单 app + 单空间 + 极致冷启动/吞吐）。
Unikernel 恰好同时继承了「libOS 编进镜像」（外核）与「单地址空间零切换」（SASOS）两支血统。
