# F3 · 外核（Exokernel）：内核只发资源句柄，抽象交给 libOS

> 形态认知专题 · 第 3 形态 —— host 软件直觉 demo（不是完整内核）。
> 一句话母题：**内核当「裁判」不当「独裁者」——它只安全地把裸资源（块/页/时间片）
> 分给各方并校验边界，至于这些资源被当成「文件 / 堆 / 页表」用，是应用自带 libOS 的自由。**

## 0. 这个形态在讲什么

把内核做「减法」推到一极：宏内核什么都管（fs/vm/net/sched 全在内核，强加给所有应用），
微内核只留 IPC+调度+地址空间，而**外核（Engler & Kaashoek, SOSP'95）几乎什么抽象都不给**——
内核只负责两件事：

1. **安全多路复用裸资源**：把物理页 / 磁盘块 / CPU 时间片 / 网卡帧发给不同应用。
2. **保护检查**：裁定边界、不重叠、谁拥有谁能用。

文件系统、虚拟内存、进程、网络栈这些**抽象**全部下放到应用自带的 **libOS** 用户态库里。
好处：不同应用能用**最合身**的抽象（数据库自管磁盘布局、高性能网络绕过内核协议栈）；
代价：抽象的复杂度搬到了每个应用，门槛高，30 年没成主流——但思想活在
Unikernel / DPDK / eBPF 里。代表：Aegis / Xok / MIT 6.828 **jos**。

> jos 的精神：内核给你 `sys_page_alloc`（一个**物理页**）却不给 `malloc`/`mmap`/堆；
> 给你块却不给「文件系统」——抽象你自己在 libOS 里拼。

## 1. 这个 demo 怎么把「本质权衡」演出来

用最朴素的软件模型：一块「磁盘」= `NBLK=16` 个块、每块 `BS=4` 字节。

- **子实验 1（`EXO_PASS`）—— exo 内核当裁判**：`exo_alloc(owner, who, start, len)`
  把块区间发给某个 owner。它**只**校验「越界」（`start+len ≤ NBLK`）和「重叠」
  （区间内每块都空闲），合法就标记归属、返回成功；越界/重叠一律拒绝且不改动。
  内核全程**不关心**这些块要拿来干嘛。
- **子实验 2（`LIBOS_PASS`）—— 两个 libOS、同样资源、不同抽象**：exo 把磁盘分成
  两段不重叠的块区间发给 libA、libB。两者在**各自**的块上建**不同**的文件抽象：
  - **libA = 顺序（sequential）布局**：文件占连续升序块（如 `f1 → [0,1]`）。
  - **libB = 分块（scatter）布局**：文件块从领地尾部倒序挑（如 `f1 → [11,10]`）。

  两种布局对**同一份数据**给出**不同的物理块映射**，却都能正确读回 → 证明
  「同样的裸资源、不同的抽象」。再校验隔离：每个 libOS 只碰自己被发放的块。

## 4. 关键约定（判题用）

- `exo_alloc`：越界用 `len > NBLK - start` 判（避免 `start+len` 溢出）；重叠要求区间内每块
  `owner == FREE`；**失败不得改动 owner 表**（外核的保护检查必须原子地「要么全发要么不发」）。
- `libb_place`：从 `base+len-1` 向 `base` 扫描挑空闲块，按采集顺序入块表（高块号在前）；
  容量不足返回 None/0 且不留脏 `used` 标记。
- 两个 libOS 的块区间由 exo **不重叠**地发放，所以同一块全局磁盘上互不踩踏（隔离）。
